Here's the one rule a trace table runs on: it gets one row per line, and a box only gets a new number in the one column that line actually changes — every other column in that row stays a dash, not a repeat of its old number. A loop gives a trace table one row per lap, not one row per line — the FOR and NEXT lines themselves don't get their own rows, they just mark where a lap starts and ends. In this program, both Count and Total change on every single lap, so watch both columns fill in together, in the same steady rhythm, all the way to the end.

Lap 3: Count becomes 3. Total becomes whatever it was after lap 2 (3), plus this lap's Count (3) — 6. Each lap's Total always builds on the lap right before it.

Cambridge's MOD is written as a function: MOD(Num, 2) gives the remainder when Num is divided by 2. This program only adds Num to Total on laps where that remainder is 0 — the even laps. On the odd laps, Total's box stays a dash. That's not a skipped row: Num still moved, so the lap still happened and still gets a row of its own — it's just Total that has nothing new to show.

Line 1: Total starts at 0. Lap 1 (Num 1): MOD(1, 2) = 1, not 0, so THEN never fires — Num becomes 1, Total stays a dash. Lap 2 (Num 2): MOD(2, 2) = 0 — Num becomes 2, Total becomes 0 + 2 = 2. Lap 3 (Num 3): odd again — Num becomes 3, Total dash. Lap 4 (Num 4): even — Num becomes 4, Total becomes 2 + 4 = 6. Lap 5 (Num 5): odd — Num becomes 5, Total dash. OUTPUT prints 6. Three laps left Total dark, and every single one of them still got its own row.
Num changes on every lap, so Num's column fills in every row without exception. Total only changes when MOD(Num, 2) = 0 is actually true that lap — on every lap where it's false, Total's box is a dash, but the row itself still belongs there.
A dash in a trace table never means "nothing happened this lap" — it only ever means "this particular column had nothing new to show." The lap itself is real either way.
