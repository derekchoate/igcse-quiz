Close an unsaved document and it's gone. Save it, and it survives a power cut.

A "power cut" is a sudden blackout — the electricity simply stops. Your computer holds two totally different kinds of memory at once, and only one of them notices when that happens. This module walks a memory city block by block: the district that forgets everything the instant power stops, the district that never forgets its one fixed job, three rival warehouses for keeping things long-term, an overflow bus that quietly kicks in when a district fills up, and a fourth district that lives on someone else's computer entirely.

RAM (random access memory) is where anything you're actively doing lives right now — the sentence you're mid-typing, the tab you have open, the level of a game you haven't saved yet. It's primary storage: memory the CPU can reach directly, without going through anything else. Everything else on the map below survives with no power at all: ROM (read only memory, also primary storage), the secondary storage built into the device itself, and anything already saved to the cloud. Only RAM is wiped by a power cut. Anything already saved — to the device's own storage, or to the cloud — survives, and so do the fixed startup instructions living in ROM. If it hasn't been saved anywhere yet, it was only ever in RAM.

RAM and ROM are both primary storage — both sit close enough to the CPU for it to reach them directly — but they do opposite jobs. RAM can be written to and rewritten constantly, and forgets everything the instant power stops. ROM holds one fixed set of instructions: the very first ones the computer follows the moment it's switched on, before it has loaded anything else at all, and its contents normally can't be changed by whoever's using the machine. That's why a computer needs both — without RAM, it would have nowhere to keep anything it's actively doing; without ROM, it wouldn't know what to do the instant it wakes up, since RAM itself starts every power-on completely empty. One thing ROM is not, by the way: a place for your files. Your photos, documents and apps all live on secondary storage — Discovery 3, coming right up. ROM's one job is those startup instructions, nothing else.

Anything about actively working, changing, or vanishing belongs to RAM. Anything about fixed startup instructions, or contents a user can't normally change, belongs to ROM.

Secondary storage isn't directly reachable by the CPU the way RAM and ROM are, but it's what actually keeps data for the long term — permanently, with no power needed. Three rival technologies do this job, each with its own honest trade-offs. Magnetic storage — the hard disk drive (HDD) — stores data on spinning platters, written and read using electromagnets: call it the spin-drive. Optical storage — CD, DVD, Blu-ray — stores data as tiny marks burned into a spinning disc, read by a laser: call it the disc. Solid-state storage — SSD, memory cards, USB drives — stores data purely in transistors, with nothing that physically spins or moves at all: call it the chip. Capacity is measured in the same units from Module 6 (gigabytes, terabytes) — worth a peek back if those feel rusty. RAM is finite — the district below holds exactly four slots. When every slot's full and one more app is opened, the computer doesn't just refuse: it creates virtual memory, quietly paging the oldest app out to secondary storage to free up a slot, then loading the new one in. Worth saying plainly, since it's an easy thing to get backwards: virtual memory is not extra RAM appearing from nowhere for free. It's a trick — borrowing space on the disk as overflow — and disk is dramatically slower than RAM, so anything paged out there costs real time to bring back. Virtual memory's whole job is keeping everything running, not making everything run fast. Press the button below until RAM fills up, then once more to trigger the overflow, and watch the tick cost.

    Try…

    Open four apps: each lands straight in an empty RAM slot for 1 tick apiece — no swapping needed, since there's room. Open a fifth: RAM has nowhere left, so the oldest app already there gets paged out to secondary storage to make space, and only then does the new app load into the freed slot — 20 ticks total this time, twenty times slower than a normal open. Nothing was lost and nothing failed; it just got noticeably slower, because disk stood in for RAM for a moment.
    Where do the extra pages actually go once RAM's four slots are all full?
    They go to secondary storage — and disk is much slower than RAM. Virtual memory keeps everything running, not running fast.

    Cloud storage means your data lives on servers owned by someone else, reachable remotely over the internet, rather than sitting only on a disk or chip inside your own device.
