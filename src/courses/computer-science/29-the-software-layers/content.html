System software provides the services the computer itself requires just to function — this includes the operating system and utility software. Application software provides the services the user wants — the things you actually opened the device to do. (Worth saying plainly: the operating system is not the wallpaper or the desktop picture you see — it's the whole engine running underneath everything, including that picture.) An interrupt is a signal that tells the CPU "something else needs attention right now" — a key pressed, a print job queued, a battery running low. The word sounds alarming, but the event itself is completely routine; your device handles dozens of these every second without you noticing. Here's exactly what happens, every time: the CPU bookmarks its place (same idea, new costume — that's the Program Counter from Module 16, saved before anything else happens), it services the interrupt (deals with whatever needs attention), and then it resumes exactly where it left off. Nothing is lost, nothing breaks — it only ever pauses. Start the task below, then fire all three kinds of interrupt while it's running.

    Interrupts like these happen dozens of times a second on every device you own. This is normal — working exactly as designed, never a fault.

Now press the other two buttons the same way, whenever you like, in any order. Each one runs the same calm three-part pattern: bookmark, service, resume.
    Watch what the CPU does in the very instant the bell rings — before it does anything about the interrupt at all.
    It wrote something down before leaving — its place in the task. That's what lets it come back afterwards and pick up exactly where it stopped, instead of starting over or losing the thread. Interrupts pause. They never destroy.

    There's an obvious-sounding alternative to interrupts: why not just have the CPU keep checking "is the printer ready yet? is it ready yet?" over and over until the answer is yes? That's called polling, and it works — but watch what it costs below. Run the same wait two ways: polling, where the CPU checks again and again, and interrupt-driven, where the CPU gets on with other useful work until the printer itself speaks up.

        Try both approaches…

        Press "Try polling the printer" — the log fills with tick after tick of "checked the printer — not ready", eight wasted checks in a row before the ninth finally finds it ready. Press "Try using an interrupt instead" — the CPU spends those same eight ticks doing other useful work, and only stops for a moment when the printer itself raises the interrupt to say it's ready. Same wait, same printer — completely different use of the CPU's time.
        Count how many of the polling log's lines are the CPU finding out nothing has changed yet.
        Polling spends CPU time asking a question that's usually "not yet" — over and over, on the off chance this is the tick it changes. An interrupt flips who does the asking: the printer speaks up when it actually has something to say, and the CPU is free until then.

        Nothing runs on nothing. Hardware needs firmware to wake it up; the operating system needs that firmware to get started; and every app needs the operating system underneath it. Firmware is permanent software built into the hardware itself, and the particular piece of firmware that starts everything off is called the bootloader. Below are four shuffled steps of what happens between switching a device on and the operating system being ready. Tap them into order, one at a time.

        Tap the step you think comes first.

        Tap "Power reaches the hardware — switches flip, but nothing has 'started' yet" first — it snaps into slot 1, because it's the very first thing that happens, before any software has run at all. Tap "Firmware (the bootloader) runs directly on the hardware and looks for the operating system" next — it snaps into slot 2, since firmware is the first software to run, sitting right on the bare hardware. Keep going the same way, always asking "what has to already be running before this step is even possible?"
        Read each step and ask what it needs underneath it to even be possible. Whichever step needs nothing running yet has to go first.
        The order is: hardware gets power → firmware (the bootloader) runs on that hardware and finds the operating system → the bootloader loads the operating system and hands over control → the operating system finishes starting up, ready for applications. Firmware and the operating system are two different layers, not the same thing wearing two names.
