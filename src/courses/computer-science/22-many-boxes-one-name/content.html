Storing 30 scores in 30 separately named boxes would be misery. So: one name, many numbered compartments.

An array is exactly that fix — one name attached to a whole row of numbered compartments, instead of a pile of separate variables like Score1, Score2, Score3… Cambridge declares one like this: DECLARE Scores : ARRAY[1:5] OF INTEGER — one name (Scores), a stated lower bound and upper bound in square brackets (1 to 5 here), and the type every compartment holds. Reach into a single compartment with its number in square brackets, exactly like any other variable: Scores[3] ← 87. Compartments are numbered from whatever lower bound you state — almost always 1, never 0 by accident. Later on, the wall grows a second dimension and becomes a grid, addressed as [row, column].

Same deal as always: no marks, no timer, no wrong answers, nothing to hand in. Tap compartments and seats however you like — nothing here can crash, not even reaching for a compartment that isn't there. Take a nudge whenever you fancy one. Stars can never be taken away.
