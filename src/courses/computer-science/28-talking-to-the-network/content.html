Your device has two names. One is burned in forever. One is only ever borrowed.

Before a device can join any network, it needs a network interface card, or NIC. No NIC means no wifi, no cable, no network.

The factory gives every NIC one address. It uses the hexadecimal shorthand from Module 2. That address never changes.

When you join a network, the network gives your device a second address. Your device keeps it only while it stays connected.

Tonight you build a small passport office and watch both addresses get issued. Then you move your device between networks. You find out which address follows you and which one stays behind.

Same deal as always: no marks, no timer, no wrong answers, nothing to hand in. Engrave, join, move, forward — none of it can be done badly. Take a nudge whenever you fancy one. Stars can never be taken away.

A MAC address (media access control address) belongs to the NIC itself. The factory gives it to the NIC. It has six pairs of hex digits, the same shorthand you decoded in Module 2.

Two halves make up a MAC address:

1. The first three pairs are the manufacturer code. It names the company that made this NIC.

2. The last three pairs are the serial code. It names this one exact unit, so no two NICs ever share an address.

An IP address (internet protocol address) is a different kind of address. Your hardware does not carry it. The network you join hands it out the moment you join.

An IP address comes in two kinds:

1. A dynamic IP address is one the network reissues when it needs to. That is why it can change. Most devices get this kind.

2. A static IP address is fixed, and the network never reissues it to anyone else. A printer everyone needs to find gets this kind. So does a server that must answer at the same place every time.

Now press "Ask for a static IP" as often as you like. You get 192.168.1.10 every time. A static IP address never moves. That is why you ask for one on purpose.

Same idea, new costume. An IPv4 address is 32 bulbs. That is four of Module 1's bytes, end to end. It allows exactly 232 different addresses.

When designers made it, that number looked bottomless. Then phones, laptops, watches, doorbells and fridges all wanted their own address. The world quietly ran out of room.

IPv6 is not IPv4 with a few extra digits added. It has 128 bulbs, which is sixteen bytes. Designers built it from scratch at a much larger scale, so this never has to happen again.

Reveal both address spaces below.

roughly 340 undecillion — a number 39 digits long. That is enough for every grain of sand on Earth, many times over.

Reveal both…

Press "Show IPv4's whole address space". You see 4,294,967,296. That is 232, four bytes' worth of bulbs. It is all the room IPv4 will ever have.

Press "Show IPv6's whole address space". The number is so large that it needs a name most people have never heard: undecillion. Designers gave IPv6 sixteen bytes instead of four.

IPv6 is not a bigger IPv4. It is a different design. It is big enough that running out is no longer a realistic worry.

Reveal IPv4 first. It is an ordinary-looking number, a few billion. You could imagine running out if enough devices asked for one.
Now reveal IPv6. Compare the two numbers by length alone. One has ten digits. The other has thirty-nine. That gap is the reason IPv6 exists.

Back to Module 13's packets, header and all. This time, something has to push each packet from your home network onto the wider network.

That is the job of a router. It reads the destination address in a packet's header. Then it sends the packet on, in the right direction.

A router does not build the message. It does not store the message. It only forwards it.

A router also connects your whole home network to the wider network. It is usually the box that hands out the IPs from Discovery 2.

Three packets wait on your home network. Each one has an address somewhere on the wider network. Operate the router and forward them, one at a time.
