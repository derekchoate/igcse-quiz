Your device has two names. One is burned in forever. One is only ever borrowed.

Before any device can join a network at all, it needs a piece of hardware called a network interface card, or NIC — no NIC, no wifi, no cable, no network, full stop. Every NIC is stamped with one address the moment it's made, in the same hexadecimal shorthand from Module 2, and that address never changes for the rest of the hardware's life. But the moment you actually join a network, something else happens too: the network hands your device a second address, one it only keeps for as long as you're connected. Tonight you'll build a little passport office and watch both addresses get issued — and discover, by moving your own device between networks, which one follows you everywhere and which one gets left behind.

Same deal as always: no marks, no timer, no wrong answers, nothing to hand in. Engrave, join, move, forward — none of it can be done badly. Take a nudge whenever you fancy one. Stars can never be taken away.

A MAC address (media access control address) belongs to the NIC itself, given to it at the factory, and it's written as six pairs of hex digits — genuinely the exact shorthand you decoded in Module 2. It's built from two halves stuck together: the first three pairs are a manufacturer code (which company made this NIC), and the last three pairs are a serial code (this one exact unit, so no two NICs anywhere ever share an address). An IP address (internet protocol address) is a completely different kind of address. It isn't built into your hardware at all — it's handed out by whichever network you join, the moment you join it. Most devices get a dynamic IP: reissued by the network as needed, which is why it can change. A handful of devices — a printer everyone needs to find, a server that has to answer at the same place every time — get a static IP on purpose: fixed, and reissued to nobody else. Same idea, new costume: an IPv4 address is just 32 bulbs — four of Module 1's bytes glued end to end — which allows exactly 232 different addresses. When that system was designed, that number looked bottomless. Then phones, laptops, watches, doorbells and fridges all started asking for their own address, and the world quietly ran out of room. IPv6 isn't IPv4 with a few extra digits stapled on — it's 128 bulbs, sixteen whole bytes, built from scratch at a completely different scale so this never has to happen again. Reveal both…

Press "Show IPv4's whole address space": 4,294,967,296 — that's 232, four bytes' worth of bulbs, all the addressing room IPv4 will ever have. Press "Show IPv6's whole address space": a number so large it needs a name most people have never heard — undecillion — because IPv6 was built with sixteen bytes instead of four. It's not a bigger IPv4; it's a different design, sized so running out is no longer a realistic worry.
Reveal IPv4 first and notice it's a perfectly ordinary-looking number — a few billion, the kind you could imagine running out of if enough devices show up wanting one.
Now reveal IPv6 and compare the two numbers by length alone, before even reading them — one has ten digits, the other has thirty-nine. That gap in scale is the entire reason IPv6 exists.

Back to Module 13's packets, header and all — but this time, something has to actually push each packet from your home network onto the wider network it's addressed to. That's a router's job: it reads the destination address sitting in a packet's header, and sends that packet on, in the right direction — it doesn't build the message and it doesn't store it, it just forwards it. A router also connects your whole home network to that wider network in the first place, and it's usually the very box handing out the IPs from Discovery 2.
