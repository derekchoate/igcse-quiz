Interpreter: best for catching problems the moment you reach them while still writing; runs and translates one line at a time so results appear immediately; has to be present every time the program is used. Development convenience versus a fast, independent finished program — that's the real trade, not simply "one is better".

      An assembler is the small, single-purpose translator that turns an assembly language program into machine code — nothing else. It's easy to assume it can also handle a high-level language like Discovery 1's pseudocode, but it can't: an assembler only ever reads assembly language, one mnemonic at a time, and produces exactly one machine code instruction for each one it reads. No decisions, no rewriting — pure one-for-one substitution. Here's the mnemonic table it works from, stated plainly: LOAD → 0001, ADD → 0010, STORE → 0011 (the address afterwards is carried straight across in binary, unchanged).
